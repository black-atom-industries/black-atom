# Phase 4 — Livery

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Order matters: 1 → 2 → 3 → 4 → (5 ∥ 7) → 6.

**Goal:** `livery_core` (no tauri) holds the logic; themes ship inside the binaries and unpack to `$XDG_DATA_HOME/black-atom/themes/`; the fetch path is gone; a `livery` CLI covers apply/list/status/setup with a picker; CLI/GUI parity is pinned by a `Capability` enum; the Neovim settings page writes `vim.g.black_atom_core_config` into a managed block.

**Architecture:** Cargo workspace members `livery/core` (crate `livery_core`), `livery/cli` (bin `livery`), `livery/src-tauri` (bin `livery-gui`, lib `livery_lib`, thin `#[tauri::command]` wrappers). Embedding via `include_dir!` per adapter behind a lookup table in `livery_core::themes::embedded`. XDG paths from a small helper honouring `$XDG_CONFIG_HOME` / `$XDG_DATA_HOME` with `~/.config` / `~/.local/share` fallbacks on every platform.

**Tech Stack:** Rust 2021, tauri 2.11, tauri-specta rc.20, specta rc.20, clap 4, inquire 0.7, include_dir 0.7, dirs 6.

- `cargo fmt` clean, `cargo clippy --workspace -- -D warnings` clean, `cargo test --workspace` green, `deno task check`/`deno task test` green before every commit (pre-commit hook enforces).
- Rust style: match the existing modules; fixture-based tests per `.claude/skills/backend-testing/SKILL.md`; no comments that are conversation residue.
- TypeScript: no `any`, max two positional params, TanStack Query for server state, `livery/src/AGENTS.md` conventions; never import `@tauri-apps/plugin-fs`.

- Facts about today's crate: `.superpowers/sdd/p4-facts.md` (read it first, every task).

## Decisions (binding, recorded in MIGRATION.md)

- XDG resolution: `livery_core::paths::{config_home(), data_home()}` = `$XDG_CONFIG_HOME` else `home/.config`, `$XDG_DATA_HOME` else `home/.local/share` (`dirs::home_dir()` for home). Livery config: `config_home()/black-atom/livery/config.json`. Themes: `data_home()/black-atom/themes/<adapter>/`. (`dirs::config_dir()` is `~/Library/Application Support` on macOS, which is not what the issue or Nik's dotfiles expect.)
- Embedded set: ten adapters. Nine `themes/` dirs (ghostty, herdr, lazygit, niri, obsidian, tmux, waybar, wezterm, zed), nvim `colors/` + `lua/` (the colorschemes require the runtime under `lua/black-atom/`), obsidian additionally root `theme.css` + `manifest.json`. Unpack rule: files named `black-atom-*`, plus obsidian's two root files, plus everything under nvim `lua/`; nothing else (templates, READMEs stay embedded but unwritten). Unpack when `<themes>/.version` is missing or differs from `CARGO_PKG_VERSION`; per-adapter dir is replaced atomically (write to `.staging-<adapter>`, rename).
- Nvim becomes `Linked` with `LinkedPlacement::PackDir`: symlink `data_home()/nvim/site/pack/black-atom/start/black-atom` → `data_home()/black-atom/themes/nvim`. Neovim adds `pack/*/start/*` to the runtimepath itself.
- Frontend still needs per-app provisioning + link state for the adapter pages: `get_themes_status` is replaced by `get_app_status` in `livery_core::themes` returning `{ app, provisioning, linked: bool }[]` (no download fields, no greeting). The issue's deletion list is honoured for the download surface; the status name changes so nothing pretends to be the old thing.
- Neovim settings live in livery config `apps.nvim.settings` (typed `NvimSettings`), written into a managed Lua block in `apps.nvim.settings_path` (default `~/.config/nvim/init.lua`), block markers `-- BEGIN BLACK ATOM LIVERY CONFIG` / `-- END BLACK ATOM LIVERY CONFIG`. The colorscheme line patch (existing `match_pattern`/`replace_template`) stays as it is.
